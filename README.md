# 군집은 서로를 어떻게 아는가 — UWB 실내 군집 인터랙티브 교재

실내 강당에서 **Crazyflie 2.1 Brushless** 5대를 **UWB(Loco Positioning System)** 로 측위해 군집 비행을 하려는 동아리 부원을 위한 웹 교재입니다.
"노이즈가 섞이고, 늦게 오고, 가끔 빠지는 UWB 위치 정보만으로 5대가 안전하게 대형을 유지하려면 무엇이 얼마나 좋아야 하는가?"라는 질문에 **숫자로 답하는 법**을 익힙니다.

- 본문은 한국어, 오른쪽 위 `EN` 버튼으로 영어 전환
- 모든 데모·수식·Python 채점이 브라우저 안에서 돕니다. **실행 중 네트워크 요청 없음**(오프라인 동작)
- 화면의 모든 수치에 출처 배지: `문헌`(확인한 문헌) · `유도`(교재 안에서 계산) · `예시값`(출처 없는 가정, 회색)

**바로 보기(휴대폰 가능): https://fieihejif2.github.io/swarm-uwb-textbook/** — `main` 에 푸시하면 GitHub Actions(`.github/workflows/pages.yml`)가 자동으로 다시 배포합니다.

## 실행 방법

필요한 것: **Node.js 20 이상**. (검증 스크립트를 돌리려면 Python 3.10 이상도 필요합니다.)

```bash
npm install
```

```bash
npm run dev
```

브라우저에서 `http://localhost:5173/` 을 엽니다.

빌드한 정적 사이트를 보려면:

```bash
npm run build
```

```bash
npm run preview
```

`http://localhost:4173/` 에서 `dist/` 가 열립니다. `dist/` 폴더는 어떤 정적 웹 서버에 올려도 됩니다(경로가 모두 상대 경로).
인터넷이 없어도 동작하지만, 브라우저 보안 정책 때문에 `dist/index.html` 을 **더블클릭해서(file://) 여는 방식은 동작하지 않습니다.** 반드시 위처럼 로컬 서버로 여세요.

> `npm run dev` / `npm run build` 는 시작할 때 `scripts/prepare-assets.mjs` 로 Python 런타임(Pyodide)과 numpy 를 `public/pyodide/` 에 준비합니다. zip 으로 받은 프로젝트에는 이미 들어 있어 내려받지 않습니다. 폴더를 지웠다면 이때 한 번 numpy 휠(약 3 MB)을 받아 sha256 을 확인합니다.

## 확인용 명령

| 명령 | 하는 일 |
|---|---|
| `npm run verify` | TypeScript 시뮬레이션 엔진을 Python(numpy/scipy) 독립 구현과 교차검증. 처음 실행하면 `verify/.venv` 가상환경을 만들고 numpy·scipy 를 설치합니다. `-- -v` 를 붙이면 검사 항목을 모두 출력 |
| `npm run test` | 엔진 단위 테스트, 교재 구조·출처 검사, 손코딩 과제 채점기 테스트(정답 통과 / 일부러 틀린 코드 탈락 / 경계 사례) |
| `npm run test:smoke` | 헤드리스 Chromium 으로 빌드 결과물의 모든 챕터를 열어 데모 조작, 과제 정답 제출, 콘솔 에러 0·외부 요청 0 확인, `screenshots/` 에 데스크톱(1440px)·모바일(390px) 스크린샷 저장. 먼저 `npm run build` 와 `npx playwright install chromium` 이 필요 |
| `npm run zip` | `node_modules` 를 뺀 프로젝트를 `swarm-uwb-textbook.zip` 으로 묶기 |

## 교재 구성

| 장 | 제목 | 핵심 | 손코딩 과제 |
|---|---|---|---|
| 0 | 왜 무너지는가 | 완벽한 정보 → 지연 → 노이즈 → 손실, 4단계로 대형 무너뜨려 보기 | – |
| 1 | UWB는 거리를 어떻게 재나 | 비행시간, SS/DS-TWR, 클럭 드리프트, 1 ns ≈ 30 cm | DS-TWR 거리 계산 |
| 2 | 거리에서 위치로 | 삼변측량, 가우스-뉴턴, TDoA 쌍곡선, DOP, 앵커 높이 | 가우스-뉴턴 위치 추정 |
| 3 | TWR vs TDoA, 5대를 띄우면 | 태그 수와 갱신율, TDoA 의 공간 제약 | 모드별 드론당 갱신율 |
| 4 | NLOS, 다중경로, 이상치 | 양의 편향, 마할라노비스 게이팅, 강건 추정 | 게이팅이 들어간 측정 갱신 |
| 5 | UWB + IMU 융합 | EKF, tight vs loose, Q/R, 지연 측정 재전파 | 지연 측정을 처리하는 KF |
| 6 | Crazyflie에 넣기 | 온보드 추정, 측정 모델, Crazyradio, Crazyswarm2 (개념 모델) | TDoA 측정 모델로 칼만 갱신 1스텝 |
| 7 | 통신, 그리고 지연 아래의 합의 | 라플라시안, λ₂, 지연 한계 π/(2kλ_N), 손실 모델 | 지연 여유 계산, 길버트-엘리엇 |
| 8 | 안전 거리 예산 | 오차 합산, 다운워시 타원체, CBF, 외삽 | 2대 사이 CBF 필터 |
| 9 | 우리 시스템 측정하기 | 지상 측정 절차, CSV 로그 피팅 → 설정 반영 | 로그에서 지연과 σ 추정 |
| – | 우리 시스템 리포트 | 지금 설정의 오차 예산·권장 간격·지연 여유·DOP 요약 (인쇄/PDF) | – |

각 장은 같은 순서입니다: 학습 목표 → 예측 먼저 → 데모 → 유도 → 손코딩 과제 → 함정 실험실 → 오차 예산에 더하는 항목 → 3줄 요약과 다음 장으로 넘어가는 질문.
화면 아래의 **오차 예산** 막대는 장을 읽을 때마다 채워지고, 마지막 **우리 시스템 리포트**는 브라우저의 인쇄 기능으로 PDF 로 저장할 수 있습니다.

## 설정값 바꾸는 법

- 오른쪽 위 **⚙ 설정**: 강당 크기, 앵커 개수와 3D 위치, UWB 모드(TWR/TDoA), 노이즈·NLOS, 측위 지연, 통신 구조·지연·손실 모델, 기체(프리셋: Crazyflie 2.1 Brushless / 사용자 정의), 대형과 간격, 안전 여유. 바꾸는 즉시 모든 장의 데모와 오차 예산이 다시 계산됩니다.
- 본문과 오차 예산의 회색 **예시값** 배지를 누르면 "설정에서 바꾸기"로 해당 입력으로 바로 갑니다.
- 2장에서는 평면도의 앵커를 끌어서, 9장에서는 측정 로그(CSV)를 피팅한 결과를 "설정에 반영" 버튼으로 넣을 수 있습니다.
- **JSON 내보내기 / 불러오기**: 설정 패널 위쪽 버튼. 내보낸 파일(`swarm-system-config.json`)은 `src/sim/config.ts` 의 `SystemConfig` 구조이며 단위는 모두 SI(m, s, kg, Hz)입니다. 불러올 때 형식이 틀린 항목은 기본값을 유지하고 어떤 항목인지 알려 줍니다.
- 설정은 브라우저의 `localStorage` 에 저장됩니다. **기본값으로** 버튼으로 초기화합니다.
- 기본값 자체를 바꾸려면 `src/sim/config.ts` 의 `defaultConfig()` 를, 입력 범위·단위·표시 이름은 `src/app/fields.ts` 를 고칩니다.

## CSV 형식 (9장 "내 데이터 넣기")

업로드한 파일은 **브라우저 안에서만** 처리됩니다(서버 전송 없음). 첫 줄은 열 이름, `#` 으로 시작하는 줄은 주석, 구분자는 쉼표·세미콜론·탭.

| 로그 | 열 | 단위·기준 |
|---|---|---|
| 정지 로그 | `t,x,y,z` | 초, 미터. 기체를 고정해 두고 기록한 위치 추정값 |
| 거리 로그 | `t,anchor_id,range_m` | 초, 정수 id, 미터. 앵커별 참 거리는 화면에서 입력 |
| 지연·손실 로그 | `seq,t_send,t_recv` | 일련번호, 초. **두 시각 모두 같은 PC 시계**로 잰 왕복 시각. 빠진 `seq` 는 손실로 계산 |

자세한 설명과 샘플 파일은 [`docs/CSV_FORMAT.md`](docs/CSV_FORMAT.md) 와 `public/samples/` 에 있습니다.

## 폴더 구조

```
src/sim/        시뮬레이션 엔진 (UI 와 분리된 순수 TypeScript, Node 에서도 동작)
src/sim/mc/     몬테카를로 실험 (Web Worker 에서 실행)
src/chapters/   챕터 0~9 (본문, 데모, 손코딩 과제와 채점 케이스)
src/ui/         공용 UI (출처 배지, 수식, 그래프, 평면도, 3D, 코드 과제, 몬테카를로 패널)
src/app/        전역 설정 저장소, 한/영 전환, 라우팅
src/py/         Pyodide 채점 하니스와 워커
src/data/       sources.json — SOURCES.md 의 기계 판독본
verify/         Python 기준 구현과 교차검증 스크립트
tests/          단위 테스트, 채점기 테스트, 브라우저 스모크 테스트
docs/           AUTHORING.md(챕터 작성 지침), CSV_FORMAT.md
screenshots/    스모크 테스트가 저장한 최종 스크린샷
```

- [`REVIEW_LOG.md`](REVIEW_LOG.md) — 품질 루프(초보 부원 / 기술 검증 / 출처 감사 / UX 리뷰)의 지적과 조치 기록

## 이 교재가 하지 않는 것

- Crazyflie 펌웨어나 Crazyswarm2 의 내부 동작을 재현하지 않습니다. 6장은 개념 모델이며 실제 절차는 공식 문서를 따르세요.
- 교재의 수치 중 회색 **예시값**은 출처가 없는 가정입니다. 실제 비행 전에 9장의 절차로 직접 측정해 바꿔야 합니다.
